====================================================
  CIVICPULSE-BRICS — BACKEND FOLDER
====================================================

PURPOSE:
  This folder contains ALL the Python server-side logic for the platform.
  It is the brain of CivicPulse-BRICS — handling API routes, AI integrations,
  databases, messaging, and all business logic.

----------------------------------------------------
  FILES IN THIS FOLDER
----------------------------------------------------

1. server.py
   PURPOSE : Main FastAPI/Starlette web server. Defines every API route
             (/api/complaints, /api/demands, /api/brics, etc.), handles
             form submissions, file uploads, authentication, and serves
             all HTML pages.
   USED BY : Render (cloud deployment), Dockerfile (CMD), app.py (import),
             All frontend pages (citizen.html, government.html, etc.)
             via HTTP fetch() calls.

2. api_client.py
   PURPOSE : Core database engine. Contains ALL SQLite read/write
             functions (CRUD) for complaints, users, SLA tracking,
             votes, and resolutions. Acts as the data access layer.
   USED BY : server.py (imports all DB functions),
             sms_gateway.py (reads complaint data),
             demands_engine.py (imports complaint helpers).

3. app.py
   PURPOSE : Lightweight entry point / runner script. Imports the ASGI
             app from server.py and starts the uvicorn server for local
             development.
   USED BY : Local development (python app.py). Dockerfile uses server.py
             directly via uvicorn in production.

4. brics_context.py
   PURPOSE : BRICS geopolitical data store. Defines the metadata for all
             9 BRICS+ nations (codes, capitals, currencies, languages,
             infrastructure sectors, urban centers). Used to personalize
             the portal per country.
   USED BY : server.py, brics_proposals_engine.py, megaplan_engine.py,
             budget_engine.py.

5. brics_proposals_engine.py
   PURPOSE : Manages inter-city and cross-BRICS project proposals. Handles
             CRUD for city-level proposals, BRICS joint project requests,
             voting, and status updates. Reads/writes city_proposals.json
             and brics_incoming_requests.json.
   USED BY : server.py (API endpoints for /api/city/proposals,
             /api/brics/proposals).

6. demands_engine.py
   PURPOSE : Manages community demand proposals made by citizens. Handles
             read/write of demands.json, upvoting logic, and country
             filtering.
   USED BY : server.py (API endpoints for /api/demands).

7. megaplan_engine.py
   PURPOSE : AI-powered city infrastructure planning engine. Uses Gemini AI
             to synthesize large-scale urban development plans (MegaPlans)
             from complaint data and BRICS context. Generates structured
             JSON plans.
   USED BY : server.py (AI plan generation endpoints).

8. budget_engine.py
   PURPOSE : Calculates and validates infrastructure project budgets. Provides
             cost estimation logic and budget category breakdown for
             city proposals and community demands.
   USED BY : server.py, brics_proposals_engine.py.

9. gemini_helper.py
   PURPOSE : Centralized wrapper for Google Gemini AI API calls. Provides
             retry logic, fallback handling, and a unified interface for
             all AI-driven features across the platform.
   USED BY : server.py, megaplan_engine.py, brics_proposals_engine.py,
             tts_helper.py.

10. messaging_gateway.py
    PURPOSE : Handles all outbound messaging — WhatsApp notifications,
              SMS alerts, and push notifications for complaint status
              updates. Integrates with Twilio / messaging APIs.
    USED BY : server.py (triggered on complaint submission and resolution).

11. sms_gateway.py
    PURPOSE : Dedicated SMS module. Manages SMS log storage in the SQLite
              database, sends SMS via Twilio API, and provides endpoints
              to check SMS delivery status.
    USED BY : server.py (/api/sms/* endpoints), messaging_gateway.py.

12. tts_helper.py
    PURPOSE : Text-to-Speech helper. Converts AI-generated complaint
              summaries and status updates to audio using Google Cloud TTS
              or Gemini. Enables voice accessibility for the portal.
    USED BY : server.py (audio narration endpoints).

13. public_data_helper.py
    PURPOSE : Fetches live public data (weather, air quality, etc.) from
              external open APIs. Enriches complaint reports with
              real-time environmental context.
    USED BY : server.py (injected into complaint context before AI triage).

14. dpg_spec.py
    PURPOSE : Digital Public Good (DPG) specification generator. Produces
              structured documentation and API specs proving CivicPulse-BRICS
              complies with DPG Alliance standards.
    USED BY : server.py (/api/v1/openapi.json endpoint).
