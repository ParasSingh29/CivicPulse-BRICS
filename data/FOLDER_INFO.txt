====================================================
  CIVICPULSE-BRICS — DATA FOLDER
====================================================

PURPOSE:
  This folder stores all persistent runtime data files — databases and
  JSON flat-files that are read and written by the backend during live
  operation. These files are NOT committed to version control for
  production (databases are managed by the cloud environment).

----------------------------------------------------
  FILES IN THIS FOLDER
----------------------------------------------------

1. civicpulse.db  [SQLite Database — PRIMARY]
   PURPOSE : The main production database for CivicPulse-BRICS. Stores:
             - All citizen complaints (with status, photos, SLA data)
             - Registered user accounts (citizens, city officials, gov officials)
             - SMS logs
             - Complaint resolution records and engineer assignments
             - Voting records
   USED BY : api_client.py (all CRUD operations via DB_FILE constant),
             sms_gateway.py (SMS log reads/writes).

2. civic_pulse_users.db  [SQLite Database — LEGACY/BACKUP]
   PURPOSE : An older or backup user database from an earlier version of the
             platform. Kept for reference and rollback purposes.
   USED BY : Not actively used; retained for data integrity.

3. demands.json  [JSON Flat-file]
   PURPOSE : Stores all community demand/project proposals submitted by
             citizens. Each entry includes title, sector, address, GPS
             coordinates, description, upvote count, and author.
   USED BY : demands_engine.py (reads/writes via DEMANDS_FILE constant),
             server.py (API: GET /api/demands, POST /api/demands).

4. city_proposals.json  [JSON Flat-file]
   PURPOSE : Stores city-level infrastructure project proposals submitted by
             city officials for review by central government. Includes
             proposal metadata, budget estimates, sector, and status.
   USED BY : brics_proposals_engine.py (CITY_PROPOSALS_FILE constant),
             server.py (API: GET /api/city/proposals, POST /api/city/proposals).

5. brics_incoming_requests.json  [JSON Flat-file]
   PURPOSE : Stores incoming cross-border BRICS joint project requests from
             other BRICS nation nodes. Tracks collaboration proposals
             awaiting review by the Central Government Hub.
   USED BY : brics_proposals_engine.py (BRICS_INCOMING_FILE constant),
             server.py (API: /api/brics/proposals).
